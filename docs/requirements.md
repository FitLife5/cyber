# Специфікація вимог до ПЗ «CyberShield AI»

## 1. Призначення і межі
**Призначення:** Прискорення первинного розбору інцидентів інформаційної безпеки та стандартизація дій реагування для SOC-аналітиків за допомогою AI-асистента та векторної бази знань (RAG).

**Що входить у межі проєкту:**
* Вебінтерфейс для вводу сирих логів та завантаження `.log`/`.txt` файлів.
* Автоматичне маскування чутливих даних (паролів, API-ключів) у тексті логів перед аналізом.
* Векторний пошук релевантних інструкцій реагування (Playbooks) у базі знань Qdrant.
* AI-генерація структурованого звіту (рівень загрози, тип атаки, план дій).
* Інтерфейс керування базою знань (додавання нових текстових регламентів).
* Локальне збереження історії останніх перевірок у браузері користувача.

**Що свідомо НЕ входить у межі проєкту:**
* Мобільний застосунок (iOS / Android).
* Автоматичне втручання в інфраструктуру (самостійне виконання команд блокування на серверах без участі людини).
* Монетизація, платіжні шлюзи та система платних підписок.
* Складна багатокористувацька авторизація через OAuth/SSO.

## 2. Користувачі та зацікавлені сторони
* **SOC-аналітик (Основний користувач):** Спеціаліст першої лінії підтримки безпеки. Ціль — швидко зрозуміти суть інциденту з логу та отримати перевірені команди для локалізації загрози.
* **Адміністратор безпеки (Власник бази знань):** Старший інженер. Ціль — наповнювати та актуалізувати внутрішні інструкції реагування (Playbooks), на які спирається AI.

## 3. Функціональні вимоги (FR)
* **FR-01 [Must]:** Система повинна надавати SOC-аналітику текстове поле для вставки фрагмента логу обсягом до 10 000 символів.
* **FR-02 [Should]:** Система повинна дозволяти SOC-аналітику завантажувати файли журналів подій у форматах `.log` та `.txt` розміром до 2 МБ.
* **FR-03 [Could]:** Система повинна надавати SOC-аналітику щонайменше 3 попередньо заготовлені шаблони тестових логів для швидкої демонстрації аналізу.
* **FR-04 [Must]:** Система повинна автоматично замінювати знайдені в тексті логу паролі, токени та секретні ключі на маркер `[REDACTED]` до моменту передачі даних до LLM.
* **FR-05 [Must]:** Система повинна виконувати семантичний пошук у векторній базі знань та знаходити 2 найбільш релевантні інструкції реагування для введеного логу.
* **FR-06 [Must]:** Система повинна генерувати за допомогою LLM структурований звіт, що містить рівень критичності (`CRITICAL`, `WARNING`, `SAFE`), назву типу атаки та опис інциденту.
* **FR-07 [Must]:** Система повинна формувати у звіті нумерований перелік рекомендованих дій із можливістю копіювання кожної команди в буфер обміну одним кліком.
* **FR-08 [Must]:** Система повинна відображати у звіті назву інструкції з бази знань, на основі якої було сформовано рекомендації.
* **FR-09 [Must]:** Система повинна надавати Адміністратору безпеки форму для додавання нової інструкції реагування (назва та текст) до векторної бази знань.
* **FR-10 [Could]:** Система повинна зберігати історію 5 останніх проаналізованих інцидентів у локальному сховищі браузера користувача.

## 4. Нефункціональні вимоги (NFR)
* **NFR-01 [Must] (Продуктивність — часова ефективність):** Повний цикл аналізу логу (маскування, пошук у базі знань та отримання відповіді від LLM) повинен тривати не більше 10 секунд у 90 % запитів за довжини логу до 3 000 символів.
* **NFR-02 [Must] (Безпека — конфіденційність):** 100 % виявлених за регулярними виразами паролів та ключів доступу повинні бути видалені з тексту запиту до зовнішнього API провайдера LLM.
* **NFR-03 [Must] (Надійність — стійкість до відмов):** У разі недоступності зовнішнього LLM-провайдера або перевищення ліміту запитів (HTTP 429) система повинна відображати користувачу зрозуміле повідомлення про помилку протягом 2 секунд без аварійного завершення роботи інтерфейсу.
* **NFR-04 [Should] (Зручність використання — зрозумілість):** Новий SOC-аналітик повинен мати змогу виконати перший аналіз тестового логу та скопіювати рекомендовану команду не довше ніж за 2 хвилини без попереднього навчання.
* **NFR-05 [Must] (Функціональна придатність / AI-складова — повнота):** Звіт, згенерований LLM, повинен відповідати заданій JSON-схемі без синтаксичних помилок у 98 % запитів та формуватися українською мовою.

## 5. Обмеження та припущення
* **Обмеження бюджету:** Бюджет на оплату хмарних AI API становить 0 грн; дозволено використовувати лише безкоштовні тарифи (Free Tier).
* **Обмеження ресурсів:** Розробка ведеться командою з 2 осіб протягом одного навчального семестру.
* **Припущення:** Користувачі взаємодіють із системою через сучасні десктопні браузери за наявності стабільного інтернет-з'єднання.
