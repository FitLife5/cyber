# ADR-0002. Ізоляція звернень до LLM-провайдера в окремому модулі

**Статус:** Прийнято

**Контекст:**
Система працює з чутливими логами безпеки та використовує зовнішній «LLM-провайдер» (див. C4 Context та Container). Можлива заміна хмарної моделі (Gemini) на локальну (Ollama) без зміни решти коду.

**Рішення:**
Винести всю логіку взаємодії з LLM в окремий «AI / RAG-модуль» на сервері через абстрактний базовий клас `BaseLLMProvider`. Веб-застосунок (React) ніколи не звертається до LLM напряму; API-ключі зберігаються виключно у змінних середовища сервера.

**Альтернативи:**
- *Прямі запити з React до API моделі* — критично відкинуто через неминучий витік API-ключів у коді клієнта та неможливість маскування секретів перед відправкою.
- *Виклик бібліотеки провайдера безпосередньо в роутах FastAPI* — відкинуто, оскільки зміна моделі вимагала б переписування бізнес-логіки ендпоінтів.

**Наслідки:**
- (+) Повна безпека ключів, легка підміна провайдера та централізований підрахунок використаних токенів.
- (−) Необхідність підтримувати додатковий шар абстракції та мапінгу відповідей.
